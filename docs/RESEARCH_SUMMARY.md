# npuloop — 모의 양자화와 정수 실행을 구분해서 검증하기

윤기혁 · 개인 연구·개발 프로젝트 · 모빌린트 Deep Learning Research Engineer 지원용 프로젝트 설명

## 해결하려던 문제

모델을 INT8로 바꾼 뒤 모의 양자화의 정확도가 유지돼도, 내보낸 정수 프로그램이 같은 텐서를 만드는지는 별개의 문제였습니다. 모델의 구조를 바꿨을 때도 MAC 수의 감소만으로 특정 배열 구성에서 실행 비용이 얼마나 줄어들지 판단하기 어려웠습니다. npuloop은 가상 NPU 제약을 이용한 구조 분석과 정수 실행의 정확도 검증을 한 흐름으로 연결한 도구입니다.

## 구현과 측정

PyTorch 모델을 `torch.fx`로 추적하고 BatchNorm을 접어 정적 그래프로 변환했습니다. 가상 NPU 프리셋에서 연산 지원 여부와 사이클을 추정하고, 활성함수 교체와 채널 정렬 프루닝 후보의 비용을 다시 계산하도록 구성했습니다. 여기서 사이클은 실제 칩에서 잰 성능이 아니라 해석적 비용 모델의 출력입니다.

양자화한 그래프는 int8 가중치, int32 바이어스와 고정소수점 재양자화 파라미터를 갖는 정수 그래프로 내보냅니다. NumPy와 C++ 실행 경로의 정수 코드를 대조하고, 파일로 내보낸 그래프도 독립 실행형 C++ 경로에서 확인합니다. 일부 연산은 TFLite reference 경로와 외부 대조했으며, 내부 일치와 외부 검증의 범위를 따로 표시했습니다.

## 핵심 결과와 해석

기존 E15 결과에서 분류 모델 6종·양자화 방식 2종의 전체 테스트 평가를 비교했습니다. 관측 정확도 차이는 최대 0.20%p였지만 출력 정수 코드의 28.5–72.7%는 달랐습니다. 이는 정확도 유사성만으로 골든 벡터의 비트 일치를 보장할 수 없다는 결과입니다. 신뢰구간이 0을 포함했다는 사실을 정확도 동등성의 입증으로 표현하지 않습니다. **근거: 논문 표 5.2.**

가장 큰 국소 차이를 보인 LayerNorm만 정수 연산과 맞추는 개입에서는 국소 차이가 24.77%에서 0%가 됐지만 출력 코드 불일치는 72.7%에서 65.7%로만 줄었습니다. 이 결과는 LayerNorm 단독 교체의 한계를 보여줍니다. 모든 연산자의 누적 교체가 불가능하다는 뜻은 아닙니다. **근거: 논문 표 5.3.**

초해상 입력을 추가하면서 float64·float32의 나눗셈과 반올림 경계 차이가 입력 양자화기에서 문제를 일으킨다는 점을 추적했습니다. 기존 경로가 실제로 틀리는 입력을 먼저 확인하고 수정 경로의 일치를 검사하는 회귀 테스트를 두었습니다. 도구가 만든 첫 결과도 의심하고 측정 경로를 분리해 보는 과정이었습니다. **근거: 논문 6.2절 및 `tests/test_intengine.py`의 입력 양자화 회귀 테스트.**
